# 前端开发规范

## 适用范围

apps/web 承载 Web 页面，apps/api 提供 API。 本文覆盖用户可见界面、交互状态、组件职责和前端文案维护。

## 界面结构

- 主入口承载活动列表，用户先选择或创建活动，再通过数字编号入口进入活动内的大屏、提交页和管理页。
- 活动列表的设置弹窗承载轻量活动信息修改，活动名称和同学参加方式修改后应即时反馈在当前列表卡片。
- 新建活动和活动设置中的同学参加方式使用分段控件；准入名单与匿名模式需要配套短说明，避免把匿名误解为完全无姓名。
- 提交页 AI 评分区的分数主卡需要在缩放过程中保持完整宽度，排名信息不得挤压或遮挡分数。
- 组件按业务能力、通用能力和配置服务分层放置。
- 资源、测试和文档不与业务页面混放。

## 交互规范

- 用户可见文案优先使用自然、简短、面向结果的表达。
- 处理中、空状态和错误状态需要给出明确结果和下一步动作。
- 新建活动、导入名单和配置类动作需要清楚区分普通入口与管理操作。
- 修改交互、状态或视觉结构时，同步检查相关文件说明书。

## 维护规则

- 新增页面、组件或用户流程后，更新相关文件夹 README。
- 影响普通用户文案时，避免暴露内部实现细节。
