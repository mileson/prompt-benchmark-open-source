# 产品流程说明

## 核心流程

- 管理员创建或维护活动与 AI 配置。
- 运营人员从活动列表选择历史活动或新建活动，再进入对应活动的大屏、提交页和管理页。
- 运营人员可从活动列表的活动设置弹窗修改活动名称和同学参加方式，活动编号入口和历史数据归属保持不变。
- 同学参加方式支持“准入名单”和“匿名”：准入名单要求姓名已导入活动名单，匿名允许首次输入姓名时创建同学并用同名续接数据。
- 活动公开入口按创建顺序展示为 `/event/1`、`/event/2` 和 `/join/1`、`/join/2`，历史 slug 入口继续兼容访问。
- 参与者进入 Web 页面提交作品或查看活动信息。
- API 汇总参与者、提交、评估和看板数据，前端按活动状态呈现结果。

## 用户路径

- 用户从主入口进入活动列表，并围绕选定活动完成创建、处理、查看或导出。
- 新建活动只产生新的活动空间，不复制历史活动的名单、提交或评分。
- 异常、空状态和处理中状态由页面或服务层给出反馈。
- 管理类或诊断类入口服务于配置、日志、验证和后续维护。

## 状态变化

- 初始状态来自本地配置、远程数据或用户选择。
- 处理中状态记录任务进度、错误原因和可恢复动作。
- 完成状态产出可查看、保存、导出或继续编辑的结果。

## 维护规则

- 页面入口、主流程、异常恢复或导出路径变化后，同步更新本文。
- 新增跨模块流程时，同时检查 file-structure.md 和相关文件夹 README。
